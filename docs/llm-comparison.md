# Сравнение языковых моделей

Состояние на 2026-09-25. Конвейер Б2 прогнан на четырёх моделях по четырём обращениям: Qwen3-235B и Alice AI LLM через Yandex AI Studio, T-lite-it-2.1 и Qwen3-8B под llama-server на раннере GitHub Actions (`.github/workflows/llm.yml`). Все цифры ниже взяты из `results/llm/summary.json`, его собирает `pnpm report` из протоколов прогонов.

## Модели

|---|---|---|---|
| `local-t-lite` | `t-tech/T-lite-it-2.1`, GGUF Q4_K_M | llama-server на раннере GitHub | основная модель концепта |
| `local-qwen3-8b` | `Qwen/Qwen3-8B`, GGUF Q4_K_M | llama-server на раннере GitHub | пара для T-lite: та же база, дообучение Alibaba |

Пара для сравнения исправлена в CONCEPT.md §10: вместо сырой базы `Qwen3-8B-Base` берётся инструкционная `Qwen3-8B`. Остаточное смешение, то есть разные рецепты дообучения поверх одной базы, заявляется как ограничение.

Сначала обе модели 8B шли через HF Inference Providers, но бесплатных $0,10 в месяц хватило примерно на полтора обращения, а T-lite у featherless выдаёт мусор (раздел о провайдерах ниже). Теперь обе модели запускаются из одинаковой квантизации Q4_K_M под llama-server на раннере GitHub Actions. Заодно это проверка 4 на локальном рантайме: llama-server превращает `json_schema` в грамматику. Промпты отлаживаются на Yandex.

T-pro-it-2.1 в этот этап не входит. Замер памяти и контекста (проверка 5) имеет смысл только на целевой машине.

## Проверка 4: доходит ли схема до сервера

По исходникам `@ai-sdk/openai-compatible` 3.0.54 (`dist/index.js`, построение `response_format`):

- с `supportsStructuredOutputs: true` схема уходит как `response_format: {type: "json_schema", json_schema: {schema, strict: true, name}}`;
- без флага уходит только `{type: "json_object"}`, схема отбрасывается с предупреждением и в промпт не попадает.

Из этого следуют два правила конвейера. Структура ответа всегда описана в тексте промпта, иначе в режиме `json_object` модель её не узнает. Модель, чей сервер ограничивает декодирование, схему тоже не видит: llama.cpp, например, использует её только как грамматику. Отдельная обёртка над эндпоинтом не нужна, слой вызова схему передаёт.

Со стороны клиента видно только одно: что ушло в запросе. Первое тело запроса каждой стадии сохраняется в `results/runs/<run>/requests/`, а тип `response_format` каждого вызова пишется в протокол. Ограничивает ли сервер декодирование на самом деле, снаружи не доказать. Косвенный признак из §5 концепта: доля ответов, не прошедших схему, должна быть равна нулю.

AI SDK 7 тела запроса и ответа по умолчанию не возвращает. Конвейер включает их явно (`include: { requestBody: true, responseBody: true }`).

## Как устроена схема Б2

1. **Извлечение.** Один вызов на взаимодействие. На вход идут реплики с номерами и все применимые к каналу вопросы. На выходе по каждому вопросу рассуждение и список фрагментов `{turn, quote, note}`. Значение ответа на этом шаге не выбирается.
2. **Сверка по FR-46.** Сначала точное совпадение токенов в указанной реплике, затем нечёткий поиск по всему взаимодействию с порогом сходства 0,8. При нечётком совпадении адрес пересчитывается по найденному месту. Для звонка сохраняется время первого слова, туда и перематывает цитата (FR-63).
3. **Повтор по FR-48.** Если цитата не нашлась, повторно запрашиваются только вопросы с ненайденными цитатами, до трёх попыток. Модель получает свой прошлый ответ и список ненайденных цитат. Сверенные фрагменты сохраняются.
4. **Агрегация.** Один вызов на обращение. На вход идут только сверенные фрагменты с идентификаторами E1, E2 и так далее, полный текст взаимодействий модель не видит. Поле `evidence` ограничено перечнем существующих идентификаторов, поэтому сослаться на несуществующий фрагмент модель не может. Ответ без ссылок отбраковывается и запрашивается заново. Исключение: значение, которое у вопроса помечено как допустимое без доказательств.
5. **Подсчёт** выполняет детерминированный код (`src/score.ts`), модель баллы не складывает.

Б2-бп отличается одним флагом (`--scheme b2-np`): цитаты принимаются как есть, повторов нет, ответ без ссылок принимается.

## Решения, которых нет в концепте

Все пять приняты мной при реализации и вынесены сюда, чтобы их можно было оспорить.

- **Ответ без доказательств.** Для вопроса «использованы ли запрещённые формулировки» правильный ответ «нет» процитировать нечем. В концепте такого случая нет, он следует из довода FECT. Рубрика получила поле `valueWithoutEvidence`: только это значение принимается без цитаты. Долю таких ответов стоит считать отдельно.
- **Отбраковка на уровне фрагмента.** FR-48 говорит об отбраковке ответа. В Б2 цитату порождает извлечение, поэтому отбраковывается фрагмент, а агрегация ссылается уже на сверенные.
- **ё = е при сверке.** FR-46 перечисляет регистр, пробелы и пунктуацию. Замена ё на е добавлена, потому что русские тексты пишут одно слово обоими способами.
- **Порог 0,8 выбран без обучающей части.** FR-46 требует подбирать его на обучающей части набора, а набора пока нет. Число временное.
- **Коэффициенты приоритета** (10 за дефицит балла, 5 за автоматический провал, 1 за неотвеченный вопрос, 0,2 за отбракованную цитату) выбраны на глаз и сохраняются с каждым результатом (FR-53).

## Метрики этого этапа

Точности по одному-четырём обращениям не бывает, поэтому сравнение идёт по пригодности:

- доля вызовов, не прошедших схему (ожидается ноль);
- доля цитат по уровням сверки: точные, нечёткие, ненайденные;
- число повторов и доля неотвеченных вопросов;
- токены и время на обращение;
- совпадение с авторским эталоном `data/gold/`, приводится как «n из m», без процентов и интервалов;
- отдельно прогон на псевдодвижке `reference` (текст сценария вместо распознавания) против прогона на распознанном тексте: разница отбраковок показывает, сколько из них вызвано ошибками распознавания.

## Что показал этап

**Ни одна модель не выдумала ни одной цитаты.** В десяти прогонах Б2 976 цитат, не найдено ни одной, нечётких совпадений 20. Модели 8B здесь не хуже крупных. Поэтому Б2 и Б2-бп различаются в пределах шума (29 против 31 и 32 против 29 совпадений из 40), и пользу сверки на этих данных показать нельзя. Единственный случай отбраковки за весь этап: Qwen3-8B через провайдера nscale на промпте `b2-v1` выдал две ненайденные цитаты из 35, и повторный запрос их исправил. Возможно, дело в провайдере: та же модель под llama-server ни одной цитаты не выдумала. Для диплома это существенно. Главный механизм работы на синтетике почти не срабатывает, и оценивать его придётся по тому, какие ошибки он не ловит.

**Ошибка распознавания не вызывает отбраковку.** Модель цитирует тот распознанный текст, который видит, а сверка идёт по нему же, поэтому на транскриптах GigaAM (WER 2,8 % на синтезе) не отбракована ни одна цитата. Метрика концепта «доля отбраковок из-за ошибок распознавания» по построению будет около нуля. Ошибки распознавания проходят сверку молча, и мерить их надо разницей ответов на эталонном и распознанном тексте. На синтезе эта разница в пределах шума: у Qwen3-235B 29, 29 и 32 совпадения из 40 на эталоне, Yandex STT и GigaAM.

**Расхождения с эталоном в основном систематические.** Семь пар «обращение, вопрос» расходятся с эталоном почти во всех прогонах: эмпатия в трёх обращениях, обещания в двух, итог и документирование в грубом звонке. Если все модели стабильно отвечают не так, как автор, вопрос сформулирован неоднозначно. Это мера однозначности рубрики из §5 концепта. Эталон задним числом не правится, рубрику надо переписать до основного эксперимента.

**Ловушку на несколько источников поймал один прогон из двенадцати** (Qwen3-235B, Б2-бп). В демо-обращении оператор по телефону называет срок «три рабочих дня», а письмо сообщает о десяти. Извлечение находит оба фрагмента, агрегация получает их на вход и отвечает «верно». Сверка такую ошибку не ловит: цитаты настоящие, неверен вывод. Это класс ошибок, который концепт измеряет релевантностью цитаты.

**Невыполненное обещание перезвонить пропустили 6 прогонов из 12.** Qwen3-235B не пропустил ни разу, Qwen3-8B в одном прогоне из двух, Alice в трёх из четырёх, T-lite в обоих. Этот многоисточниковый вопрос различает модели лучше остальных, хотя обращение всего одно.

**T-lite-it-2.1 и Qwen3-8B почти равны:** 27 и 27 совпадений из 40 на GigaAM, 27 и 25 на Yandex STT. Разница внутри шума. T-lite отвечает на все вопросы о эмпатии, Qwen3-8B даёт оценку без ссылки на фрагмент и после повторов оставляет вопрос без ответа (8 и 6 неотвеченных против 3 у T-lite). На вход T-lite тратит на 15–20 % меньше токенов в пересчёте на вызов (2002 против 2490 и 1982 против 2338), это согласуется со сравнением токенизаторов ниже. Сравнение смешивает дообучение и токенизатор, поэтому преимущество русской специализации отсюда не следует.

**Модели 8B отстают от крупных на 2–7 совпадений из 40.** На четырёх обращениях это тоже на грани шума. Крупные модели для локального развёртывания не рассматриваются, но разница показывает, где потолок.

**Alice в 7–9 раз быстрее Qwen3-235B и тратит вдвое меньше выходных токенов** при сопоставимом совпадении с эталоном. Для роли внешней верхней границы по этим данным она удобнее. Выбор между ними всё равно делается на основном наборе.

## Находки о провайдерах

- **Yandex ограничивает декодирование.** На промпте `b2-v1` Qwen3-235B в двух прогонах из двух на одном и том же обращении застрял на поле ответа шкалы 1–5 и выдавал пробелы и табуляции до предела в 6000 токенов (224 с на вызов). Бесконечные пробелы типичны для декодирования по грамматике JSON, которая разрешает сколько угодно пробелов между лексемами. Свободная генерация так не ведёт себя. Схема требовала строку `"3"`, модель, по всей видимости, хотела написать число. В `b2-v2` ответ шкалы стал целым числом, а предел вывода снижен до 4000. Сбоев схемы больше не было.
- **T-lite-it-2.1 у featherless непригоден.** На просьбу повторить фразу дословно модель выдаёт `_xt «Кварта», меня зовут Анна. Здравствуйте, чем могу变压器?` (`results/llm/verbatim-probe.json`, три пробы из трёх испорчены). Похоже на декодирование чужим словарём. Карточка модели говорит об «optimized tokenizer», словарь у T-lite на 151 689 токенов против 151 936 у Qwen3. 43 отбракованные цитаты из 67 в том прогоне отражают хостинг, а не модель.
- **Бесплатных кредитов HF ($0,10 в месяц) хватило примерно на полтора обращения** на Qwen3-8B и T-lite. Параллельные запросы HF отклоняет с кодом 402 ещё до исчерпания кредитов. Конвейер ограничивает параллельность для HF одним запросом и повторяет 402 и 429 с паузой.
- **Docker-Space на бесплатном CPU теперь требует подписки PRO.** Локальные движки распознавания и модели 8B поэтому перенесены на раннеры GitHub Actions.

## Токенизатор T-lite и пара для сравнения

CONCEPT.md §10 выбирает пару T-lite-it-2.1 и Qwen3-8B, среди прочего, потому что «словарь не расширялся»: 151 689 токенов против 151 936. Размер почти совпадает, а содержимое нет. Сравнение файлов `tokenizer.json` (`tools/compare_tokenizers.py`, результат в `results/llm/tokenizers.json`):

- общих строк токенов 106 798, то есть около 70 % словаря, и у 106 450 из них совпадает номер;
- примерно 45 тысяч токенов T-lite заменены, среди них целые русские слова вроде «административного»;
- на текстах этого проекта T-lite тратит 1 871 токен, Qwen3-8B 2 728. Это на 31 % меньше, на отдельных текстах от 26 до 37 %.

Отсюда два вывода. Пара T-lite и Qwen3-8B смешивает вклад дообучения на русских данных с вкладом нового токенизатора, и разделить их нельзя. Концепт отвергает RuadaptQwen3 именно за замену токенизатора, а T-lite-it-2.1 её тоже сделала. Доводы §10 нужно переписать: либо принять смешение как ограничение, либо искать другую пару. Второй вывод объясняет мусор у featherless: сервер, похоже, декодирует ответ словарём Qwen3.

## Что этот этап не закрывает

- Выбор локального рантайма (Ollama, llama-server, `mlx_lm.server`) и проверка ограниченного декодирования на нём.
- Память и контекст T-pro-it-2.1 на M1 Pro.
- Точность схем с доверительными интервалами. Для неё нужен размеченный набор из §5 концепта.
- Схемы Б0, Б1 и Б-кл. Они пойдут следующим этапом, как режимы того же кода.
