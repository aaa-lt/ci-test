Пара для сравнения исправлена в CONCEPT.md §10: вместо сырой базы `Qwen3-8B-Base` берётся инструкционная `Qwen3-8B`. Остаточное смешение, то есть разные рецепты дообучения поверх одной базы, заявляется как ограничение.

Бесплатные кредиты HF составляют $0,10 в месяц. Qwen3-8B у nscale стоит $0,07 за миллион входных токенов и $0,18 за миллион выходных, контекст 40 960, `supports_structured_output: true` (API роутера HF, 2026-09-24). Этого хватит на десятки прогонов одного обращения, но не на отладку промптов. Поэтому промпты отлаживаются на Yandex, а каждую версию сразу повторяют на Qwen3-8B (Q18). Цена T-lite-it-2.1 у featherless через роутер HF не публикуется. Спишутся ли за неё бесплатные кредиты, станет ясно после первого вызова.

T-pro-it-2.1 в этот этап не входит. Замер памяти и контекста (проверка 5) имеет смысл только на целевой машине.

## Проверка 4: доходит ли схема до сервера

По исходникам `@ai-sdk/openai-compatible` 3.0.54 (`dist/index.js`, построение `response_format`):

- с `supportsStructuredOutputs: true` схема уходит как `response_format: {type: "json_schema", json_schema: {schema, strict: true, name}}`;
- без флага уходит только `{type: "json_object"}`, схема отбрасывается с предупреждением и в промпт не попадает.

Из этого следуют два правила конвейера. Структура ответа всегда описана в тексте промпта, иначе в режиме `json_object` модель её не узнает. Модель, чей сервер ограничивает декодирование, схему тоже не видит: llama.cpp, например, использует её только как грамматику. Отдельная обёртка над эндпоинтом не нужна, слой вызова схему передаёт.

Со стороны клиента видно только одно: что ушло в запросе. Первое тело запроса каждой стадии сохраняется в `results/runs/<run>/requests/`, а тип `response_format` каждого вызова пишется в протокол. Ограничивает ли сервер декодирование на самом деле, снаружи не доказать. Косвенный признак из §5 концепта: доля ответов, не прошедших схему, должна быть равна нулю.

AI SDK 7 тела запроса и ответа по умолчанию не возвращает. Конвейер включает их явно (`include: { requestBody: true, responseBody: true }`).

## Как устроена схема Б2

1. **Извлечение.** Один вызов на взаимодействие. На вход идут реплики с номерами и все применимые к каналу вопросы. На выходе по каждому вопросу рассуждение и список фрагментов `{turn, quote, note}`. Значение ответа на этом шаге не выбирается.
2. **Сверка по FR-46.** Сначала точное совпадение токенов в указанной реплике, затем нечёткий поиск по всему взаимодействию с порогом сходства 0,8. При нечётком совпадении адрес пересчитывается по найденному месту. Для звонка сохраняется время первого слова, туда и перематывает цитата (FR-63).
3. **Повтор по FR-48.** Если цитата не нашлась, повторно запрашиваются только вопросы с ненайденными цитатами, до трёх попыток. Модель получает свой прошлый ответ и список ненайденных цитат. Сверенные фрагменты сохраняются.
4. **Агрегация.** Один вызов на обращение. На вход идут только сверенные фрагменты с идентификаторами E1, E2 и так далее, полный текст взаимодействий модель не видит. Поле `evidence` ограничено перечнем существующих идентификаторов, поэтому сослаться на несуществующий фрагмент модель не может. Ответ без ссылок отбраковывается и запрашивается заново. Исключение: значение, которое у вопроса помечено как допустимое без доказательств.
5. **Подсчёт** выполняет детерминированный код (`src/score.ts`), модель баллы не складывает.

Б2-бп отличается одним флагом (`--scheme b2-np`): цитаты принимаются как есть, повторов нет, ответ без ссылок принимается.

## Решения, которых нет в концепте

Все пять приняты мной при реализации и вынесены сюда, чтобы их можно было оспорить.

- **Ответ без доказательств.** Для вопроса «использованы ли запрещённые формулировки» правильный ответ «нет» процитировать нечем. В концепте такого случая нет, он следует из довода FECT. Рубрика получила поле `valueWithoutEvidence`: только это значение принимается без цитаты. Долю таких ответов стоит считать отдельно.
- **Отбраковка на уровне фрагмента.** FR-48 говорит об отбраковке ответа. В Б2 цитату порождает извлечение, поэтому отбраковывается фрагмент, а агрегация ссылается уже на сверенные.
- **ё = е при сверке.** FR-46 перечисляет регистр, пробелы и пунктуацию. Замена ё на е добавлена, потому что русские тексты пишут одно слово обоими способами.
- **Порог 0,8 выбран без обучающей части.** FR-46 требует подбирать его на обучающей части набора, а набора пока нет. Число временное.
- **Коэффициенты приоритета** (10 за дефицит балла, 5 за автоматический провал, 1 за неотвеченный вопрос, 0,2 за отбракованную цитату) выбраны на глаз и сохраняются с каждым результатом (FR-53).

## Метрики этого этапа

Точности по одному-четырём обращениям не бывает, поэтому сравнение идёт по пригодности:

- доля вызовов, не прошедших схему (ожидается ноль);
- доля цитат по уровням сверки: точные, нечёткие, ненайденные;
- число повторов и доля неотвеченных вопросов;
- токены и время на обращение;
- совпадение с авторским эталоном `data/gold/`, приводится как «n из m», без процентов и интервалов;
- отдельно прогон на псевдодвижке `reference` (текст сценария вместо распознавания) против прогона на распознанном тексте: разница отбраковок показывает, сколько из них вызвано ошибками распознавания.

## Что этот этап не закрывает
