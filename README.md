# Talkodex, подготовительный этап

Спайки перед веб-приложением. Здесь проверяются распознавание речи и языковые модели и собирается конвейер оценки обращения, который потом переходит в приложение без переписывания. Концепция: `../CONCEPT.md`, задание этапа: `../talkodex-handoff-2026-09-24.md`.

## Состояние на 2026-09-24

Сделано и прогнано:

- `asr-service/`: нарезка по паузам и склейка по пословным меткам (FR-24), разбор стерео, пять движков за общим интерфейсом (FR-26), очистка писем (FR-16), HTTP API и пакетный запуск `python -m asr_service.batch`. 23 теста.
- `pipeline/`: единое представление трёх каналов (FR-15, FR-17), схема Б2 с отбраковкой и повтором (FR-39, FR-46…FR-48), флаг Б2-бп, подсчёт и приоритет (FR-49…FR-53), протокол вызовов (FR-75), прогон одной командой (FR-74), модели Yandex, HF и llama-server. 18 тестов.
- Четыре звонка синтезированы SpeechKit и распознаны всеми пятью движками. 150 фрагментов Open STT распознаны четырьмя локальными движками.
- Qwen3-235B и Alice AI LLM прогнаны на всех обращениях в схемах Б2 и Б2-бп, на эталонном и распознанном тексте. T-lite-it-2.1 и Qwen3-8B идут под llama-server на раннере.
- `docs/asr-comparison.md` и `docs/llm-comparison.md`: результаты и выводы.

Главные находки, подробности в документах:

- На реальной телефонии (Open STT) лучший GigaAM: WER 17,8 % против 21,1 % у T-One и 26,9 % у Whisper. На синтезе порядок другой, так что синтез для выбора движка не годится.
- T-One отдаёт метки фраз, пословные строятся собственным выравниванием и стоят 0,2–0,4 пункта WER.
- Энергетический детектор речи на коротких записях срезал тихие слова и завышал WER GigaAM на 5,6 пункта. Короткие записи теперь идут целиком, для длинных детектор надо доработать.
- Токенизатор T-lite-it-2.1 заменён примерно на 30 %. Пара с Qwen3-8B смешивает вклад дообучения с вкладом токенизатора, довод CONCEPT.md §10 нужно переписать.
- Крупные модели цитат почти не выдумывают, и на них Б2 от Б2-бп не отличается. Проверка механизма переходит на модели 8B.
- Ловушку, где сроки в звонке и письме расходятся, пропустили 5 прогонов из 6, хотя оба фрагмента были извлечены.
- Рубрика v0 неоднозначна: семь пар «обращение, вопрос» расходятся с эталоном во всех шести прогонах.

Не закрывается на этом этапе: скорость на M1 Pro (NFR-13), NFR-7 на живой речи, выбор локального рантайма на Mac, память T-pro-it-2.1.

## Где что выполняется

Трафик на этой машине ограничен, поэтому веса моделей сюда не скачиваются.

| Что | Где |
|---|---|
| синтез, Yandex STT, очистка писем, модели Yandex | эта машина, `.env` |
| GigaAM, T-One, Whisper, Open STT | GitHub Actions, `.github/workflows/asr.yml` |
| T-lite-it-2.1 и Qwen3-8B под llama-server | GitHub Actions, `.github/workflows/llm.yml` |

Репозиторий Actions: `aaa-lt/ci-test`, публичный. Локальная ветка `publish` следит за `origin/main`. Полная история до публикации лежит в локальной ветке `local-history`, в `origin` она не отправлялась, потому что содержит ID каталога Yandex. Workflow коммитят результаты обратно в `results/`, так что перед работой нужен `git pull`.

## Порядок запуска

```bash
# из корня репозитория
uv run tools/synthesize.py                                            # звонки, меньше 10 ₽
(cd asr-service && uv run --env-file ../.env uvicorn asr_service.app:app --port 8000)   # отдельный терминал
uv run tools/asr.py transcribe yandex                                 # облачная колонка
git push                                                              # asr.yml запустится сам
uv run tools/asr.py score                                             # после git pull

cd pipeline
pnpm eval --model yandex-alice --engine yandex                        # и другие модели, схемы, движки
pnpm report                                                           # results/llm/summary.json
```

`llm.yml` запускается вручную: вкладка Actions или `POST /repos/aaa-lt/ci-test/actions/workflows/llm.yml/dispatches` с полями `models`, `engine`, `scheme`, `cases`.

Тесты:

```bash
cd asr-service && uv run pytest
cd pipeline && pnpm test && pnpm typecheck
```

## Как это переходит в приложение

- `asr-service` переходит почти целиком. Добавится адаптер `mlx-whisper` для Mac, веса начнут ставиться отдельно (NFR-27), а фоновые задачи в памяти уступят место очереди, если распознавание вынесут из приложения.
- Модули `pipeline/src` становятся кодом воркеров BullMQ в NestJS. `loadCase` читает файлы, и его заменит чтение из PostgreSQL. `Protocol` пишет JSONL, и его заменит таблица протокола. `cli.ts` остаётся экспериментальной обвязкой (FR-74). Схемы Zod из `domain.ts` и `rubric.ts` задают формат хранения и API.
- Б0, Б1 и Б-кл добавятся как соседние модули рядом с `evaluate/b2.ts` с тем же интерфейсом результата.

## Решения, принятые по ходу работы

Не пересматривать без причины. Обоснование в документах `docs/`:

- T-One отдаёт метки фраз. Пословные метки строим сами из жадного CTC-пути (`tone-greedy`).
- GigaAM и T-One ставятся в одно окружение только с переопределением `numpy>=2`. Лучевой поиск T-One на numpy 2 работает.
- Запись короче окна движка идёт в движок целиком. Детектор речи нужен только для длинных дорожек, на коротких он срезает тихие слова.
- Ответ на вопрос со шкалой задаётся целым числом, а не строкой. Со строкой Qwen3-235B под ограниченным декодированием уходил в бесконечные пробелы.
- У HF параллельность ограничена одним запросом, ответы 402 и 429 повторяются с паузой.
- Структура ответа всегда описана в промпте: AI SDK в режиме `json_object` схему не передаёт.
- Вопрос может иметь значение, допустимое без цитаты (`valueWithoutEvidence`).
- Псевдодвижок `reference` подставляет текст сценария вместо распознавания, чтобы отделять ошибки распознавания от ошибок модели.
