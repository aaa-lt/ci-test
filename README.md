# Talkodex, подготовительный этап

Спайки перед веб-приложением. Здесь проверяются распознавание речи и языковые модели и собирается конвейер оценки обращения, который потом переходит в приложение без переписывания. Концепция: `../CONCEPT.md`, задание этапа: `../talkodex-handoff-2026-09-24.md`.

## Состояние на 2026-09-24

Готово и покрыто тестами:

- `asr-service/`: нарезка по паузам и склейка по пословным меткам (FR-24), разбор стерео, пять движков за общим интерфейсом (FR-26), очистка писем от цитат и подписи (FR-16), HTTP API с фоновыми задачами, образ для Space. 21 тест.
- `pipeline/`: единое представление трёх каналов (FR-15, FR-17), схема Б2 с отбраковкой и повтором (FR-39, FR-46…FR-48), флаг Б2-бп, детерминированный подсчёт и приоритет (FR-49…FR-53), протокол вызовов (FR-75), прогон одной командой (FR-74). 18 тестов.
- `data/`: демо-обращение (звонок, чат, письмо) и три коротких звонка, рубрика v0 и авторские эталонные ответы, записанные до прогонов моделей.
- `docs/`: документы сравнения с методом и выводами по исходникам. Таблицы результатов пусты.

Не сделано, потому что нужны ключи: синтез звонков, развёртывание Space, все прогоны моделей. Цифр пока нет ни одной.

Не закрывается на этом этапе совсем: скорость GigaAM на M1 Pro (NFR-13), пословная точность меток (NFR-7), выбор локального рантайма, память T-pro-it-2.1. Подробности в конце обоих документов из `docs/`.

## Что нужно сделать вручную

1. Git: задать `user.name` и `user.email` для этого репозитория (`git config --local`). Коммитов пока нет.
2. Yandex Cloud: платёжный аккаунт, каталог, сервисный аккаунт с ролями `ai.languageModels.user`, `ai.speechkit-tts.user`, `ai.speechkit-stt.user` и API-ключ для него.
3. Hugging Face: токен с правом записи (для Space и Inference Providers).
4. `cp .env.example .env` и заполнить.

## Порядок запуска

```bash
# Команды из корня репозитория, кроме шага 5
# 1. Синтез звонков, около 6 тысяч символов, меньше 10 ₽
uv run tools/synthesize.py

# 2. Служба на этой машине, в отдельном терминале: Yandex STT и очистка писем
(cd asr-service && uv run --env-file ../.env uvicorn asr_service.app:app --port 8000)

# 3. Space с локальными движками; сборка образа занимает десятки минут
uv run tools/asr.py deploy        # вписать выданный адрес в ASR_URL
uv run tools/asr.py health

# 4. Распознавание и замеры
uv run tools/asr.py transcribe    # results/transcripts/
uv run tools/asr.py bench         # Open STT внутри Space, results/asr/openstt.json
uv run tools/asr.py score         # results/asr/calls.json

# 5. Оценка обращений
cd pipeline
pnpm eval --model yandex-qwen3-235b --engine reference
pnpm eval --model yandex-qwen3-235b --engine gigaam-rnnt
pnpm eval --model hf-qwen3-8b --engine gigaam-rnnt
pnpm eval --model hf-t-lite --engine gigaam-rnnt --cases demo
pnpm eval --model yandex-qwen3-235b --engine gigaam-rnnt --scheme b2-np
pnpm report                       # results/llm/summary.json
```

Тесты:

```bash
cd asr-service && uv run pytest
cd pipeline && pnpm test && pnpm typecheck
```

## Устройство

```
asr-service/  Python. Всё, что требует моделей речи: распознавание и очистка писем.
              На Mac запускается на хосте (NFR-28), на время спайков работает в Space.
pipeline/     TypeScript. Всё, что после распознавания: единое представление,
              оценка, сверка, подсчёт, протокол.
tools/        Разовые сценарии: синтез, развёртывание, замеры распознавания.
data/         Сценарии, обращения, рубрика, эталон. Выдуманы целиком.
results/      Транскрипты, протоколы и сводки прогонов. Документы берут цифры отсюда.
docs/         Документы сравнения.
```

## Как это переходит в приложение

- `asr-service` переходит почти целиком. Добавится адаптер `mlx-whisper` для Mac, веса начнут ставиться отдельно (NFR-27), а фоновые задачи в памяти уступят место очереди, если распознавание вынесут из приложения.
- Модули `pipeline/src` становятся кодом воркеров BullMQ в NestJS. `loadCase` читает файлы, и его заменит чтение из PostgreSQL. `Protocol` пишет JSONL, и его заменит таблица протокола. `cli.ts` остаётся экспериментальной обвязкой (FR-74). Схемы Zod из `domain.ts` и `rubric.ts` задают формат хранения и API.
- Б0, Б1 и Б-кл добавятся как соседние модули рядом с `evaluate/b2.ts` с тем же интерфейсом результата.

## Решения, принятые по ходу работы

Не пересматривать без причины, обоснование в документах `docs/`:

- T-One отдаёт метки фраз. Пословные метки строим сами из жадного CTC-пути (`tone-greedy`).
- GigaAM и T-One ставятся в одно окружение только с переопределением `numpy>=2`. Работает ли при этом лучевой поиск T-One, проверяется в Space.
- Структура ответа всегда описана в промпте: AI SDK в режиме `json_object` схему не передаёт.
- Вопрос может иметь значение, допустимое без цитаты (`valueWithoutEvidence`).
- Псевдодвижок `reference` подставляет текст сценария вместо распознавания, чтобы отделять ошибки распознавания от ошибок модели.
